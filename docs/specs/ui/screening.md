## 1. 画面概要

pipeline.py --deep の実行結果（2段階スクリーニング）を表形式で表示する。  
罠フラグ・鮮度タグを色分けし、ソート・フィルタによって注目銘柄を素早く見つけられるようにする。

---

## 2. レイアウト構成

```
┌──────────────────────────────────────────────────────────┐
│ [母集団] [1段階目] [2段階目] [罠検出]  ← 4つのサマリーカード │
├──────────────────────────────────────────────────────────┤
│ 鮮度サマリー: fresh XX / normal XX / stale XX / critical XX │
├──────────────────────────────────────────────────────────┤
│ フィルタ: [全件] [normal] [suspicious] [dangerous]  XX件表示 │
├──────────────────────────────────────────────────────────┤
│ ┌──────────────────────────────────────────────────────┐ │
│ │ 順位 コード 銘柄名  業種  株価  PER PBR ROE% 配当%   │ │
│ │      スコア  罠     鮮度                              │ │
│ │ ---- 行データ × N件 -------------------------------- │ │
│ └──────────────────────────────────────────────────────┘ │
├──────────────────────────────────────────────────────────┤
│ 罠検出銘柄の詳細（罠ありの銘柄のみ表示）                   │
└──────────────────────────────────────────────────────────┘
```

## 3. コンポーネント詳細

### 3.1 サマリーカード（4枚）

| カード | 表示内容 | 強調色 |
|---|---|---|
| 母集団 | 3,745社（JPXマスター全銘柄） | gray |
| 1段階目 | 40社（ROE + PER/PBRスクリーニング） | blue |
| 2段階目（IRBANK） | X社（スコア60以上・罠検出済） | emerald |
| 罠検出 | D:X S:X N:X（dangerous/suspicious/normal件数） | amber |

### 3.2 選定の前提パネル（SelectionBasis）

テーブル最上部。この15社が**いつ・どの業種を対象に選ばれたか**を示す。

スクリーニングは実行時の業種（＝その時点のマクロ分析が推した業種）で母集団を決めるが、
マクロ分析はあとから単独で更新できる。放置すると「マクロが推す業種」と
「実際に選定に使われた業種」が食い違い、いま推していない業種の銘柄が並んでいることに気づけない。

`pipelineMeta.screenedIndustries` と `targetSectors[].code` を突き合わせて3群に分けて表示する。

| 区分 | 意味 | 色 |
|---|---|---|
| 両方に入っている業種 | 現在のマクロでも推している | emerald |
| マクロは推すが未選定 | **一度も候補に入っていない** | blue |
| 選定済みだが現在は非推奨 | 選ばれたが今のマクロは推していない | amber |

食い違いがある場合はパネル全体を amber にし、再実行コマンドを添える。
「株価更新では銘柄は入れ替わらない」ことも明記する（混同しやすいため）。
`screenedIndustries` が無い古い `data.ts` では「記録されていません」と出し、一致とは言わない。

### 3.3 鮮度サマリーバー

鮮度タグ（fresh / normal / stale / critical）と件数は、`data.ts` の保存値ではなく
`src/freshness.ts > freshnessOf(irbankDate)` で**描画のたびに今日を基準に計算する**。
以前は実行時の値を `data.ts` に凍結していたため、深掘り画面と判定が食い違っていた（BUG-013）。


| 鮮度タグ | 表示例 | バッジ色 |
|---|---|---|
| fresh | fresh X | bg-emerald-50 / text-emerald-700 |
| normal | normal X | bg-blue-50 / text-blue-700 |
| stale | stale X | bg-amber-50 / text-amber-700 |
| critical | critical X | bg-red-50 / text-red-700 |

### 3.4 フィルタボタン

| 項目 | 仕様 |
|---|---|
| 選択肢 | 全件 / normal / suspicious / dangerous |
| アクティブ状態 | bg-gray-800 / text-white |
| 非アクティブ状態 | bg-white / text-gray-500 / border-gray-200 |
| 件数表示 | フィルタ後の件数をボタン右側に表示 |

### 3.5 スクリーニングテーブル

#### カラム定義

| カラム | 型 | ソート | 説明 |
|---|---|---|---|
| 順位 | number | ▲▼ | deepScore降順のランク |
| コード | string | — | 東証銘柄コード（emerald色・モノスペース） |
| 銘柄名 | string | — | 会社名。deepScore≥70に「深掘り対象」バッジ付与 |
| 業種 | string | — | 東証33業種名 |
| 株価 | number | ▲▼ | 単位：円 |
| PER | number\|null | ▲▼ | null の場合「—」表示（ソート時は999扱い末尾） |
| PBR | number | — | — |
| ROE% | number | ▲▼ | emerald色 |
| 配当% | number | ▲▼ | blue色 |
| スコア | number | ▲▼ | deepScore。≥70=emerald、≥60=blue、未満=gray |
| 罠 | TrapFlag | — | バッジ表示（下記参照） |
| 鮮度 | FreshnessTag | — | バッジ表示（下記参照） |

#### ソート動作

- 同カラムを再クリック → 昇順/降順トグル
- 異なるカラムをクリック → そのカラムの昇順でリセット
- ソート中のカラムは emerald色 + ▲▼インジケータ表示

#### 行の背景色

| 条件 | 背景色 |
|---|---|
| dangerous の行 | bg-red-50/40（薄い赤） |
| 偶数行（normal/suspicious） | bg-white |
| 奇数行（normal/suspicious） | bg-gray-50/40 |
| ホバー時 | bg-gray-50 |

### 3.6 罠フラグバッジ

| フラグ | ラベル | スタイル |
|---|---|---|
| normal | normal | bg-emerald-50 / text-emerald-700 / border-emerald-200 |
| suspicious | suspicious | bg-amber-50 / text-amber-700 / border-amber-200 |
| dangerous | DANGEROUS | bg-red-50 / text-red-700 / border-red-200 |

### 3.7 判定不能セクション

- 表示条件：`trapUndetermined` が1件以上の銘柄が存在する場合
- 表示内容：件数バッジ、銘柄名（コード）、「ルール名: 測れない理由」の箇条書き
- 冒頭に「データが取得できず評価していない項目です。『問題なし』ではありません」と明記する
- 罠フラグが `normal` でも一次資料での確認が必要であることを示すためのセクション

### 3.8 罠検出詳細セクション

- 表示条件：`trapReasons` が1件以上の銘柄が存在する場合のみ表示
- 表示内容：罠フラグバッジ、銘柄名（コード）、スコア変動幅（例: 93→78（-15））、検出理由箇条書き
- 見出し下に判定基準を明記：10ルールのうち該当1件で suspicious（−15点）、2件以上で dangerous（−30点）

### 3.9 「深掘り対象」バッジ（廃止）

`deepScore >= 70` の銘柄に付けていたが、深掘り画面の表示条件（当時 `>= 90`）と食い違っており、
バッジが付くのに深掘り画面に出ない銘柄が発生していた（BUG-010）。
最終出力の15社は全社がEDINET深掘り済みでバッジが何も区別していなかったため撤去した。

## 4. インタラクション

| 操作 | 動作 |
|---|---|
| カラムヘッダークリック | ソートキー変更。同カラム再クリックで昇順/降順トグル |
| フィルタボタンクリック | 罠フラグでフィルタリング。件数が即時更新 |
