## 1. 画面概要

`deepScore` 90以上の銘柄を銘柄カード形式で表示する。1度に1枚展開する設計。

### 実装状況（2026-09-04 時点）

| ブロック | 状態 |
|---|---|
| カードヘッダー（順位・銘柄名・罠バッジ・株価・52週高値比・取得元・鮮度） | ✅ 実装済 |
| クイック指標6項目（PER/PBR/ROE/配当/自己資本比率/時価総額） | ✅ 実装済 |
| deepScore ゲージ（1段階目→深掘り後の増減） | ✅ 実装済 |
| **6項目評価（100点満点）** | ⚠️ **4項目65点ぶんのみ実装**（下記 3.2） |
| 財務健全性（自己資本比率・ROE・PBR・PER） | ✅ 実装済 |
| 52週レンジ内ポジション | ✅ 実装済 |
| データ取得情報（取得元・基準日・90日超警告） | ✅ 実装済 |
| 罠検出パネル（該当 / 判定不能 / 確認済み） | ✅ 実装済（2026-09-10・下記 3.3） |
| 一次資料リンク（有報・決算短信PDF） | ✅ 実装済（2026-09-10・下記 3.4） |
| 直近決算サマリー（前年同期比・通期進捗率・特別損益・業績修正） | ❌ 未実装 |
| プラス材料 / リスク要因 / 最終評価 | ❌ **実装しない**（下記） |

対象銘柄は `data.ts > screeningStocks` の全社（スクリーニング最終出力）。
以前は `deepScore >= 90` で絞っていたが、罠検出で減点された銘柄が消えるうえ、
スクリーニング画面の「深掘り対象」バッジ（70点）と食い違っていたため撤廃した（BUG-010）。

「最終評価」は実装しない方針とする。計算根拠のない推奨を出さないため（BUG-008）。
「プラス材料 / リスク要因」も、根拠となるテキスト情報を取得していないため未実装のままとする。

## 3. コンポーネント詳細

### 3.1 StockCard（銘柄カード）

#### カードヘッダー

| 要素 | 仕様 |
|---|---|
| ランク番号 | #N 形式、グレー大テキスト |
| 銘柄名 | 大テキスト・太字 |
| コード | （XXXX）形式、emerald色・モノスペース |
| 罠フラグバッジ | normal/suspicious/dangerous バッジ |
| 業種・IRBANK日付・鮮度 | サブテキスト行 |
| 株価 | 大テキスト・太字（右側） |
| 52週高値比 | 「52週高値比 -X.X%」（グレーサブテキスト） |
| 評価バッジ | 強く買い推奨=emerald / 買い推奨=blue / 様子見=amber / 見送り=red |
| 展開インジケータ | ▲（展開中）/ ▼（折りたたみ） |
| クリック | ヘッダー全体クリックで展開/折りたたみ。同時に1枚のみ展開 |

#### クイック指標バー（常時表示）

| 指標 | 表示内容 |
|---|---|
| PER | Xx倍（null の場合「—」） |
| PBR | Xx倍 |
| ROE | Xx% |
| 配当利回 | Xx% |
| 自己資本比率 | Xx% |
| 時価総額 | XXX億 |

背景：bg-gray-50。グリッド6分割。

### 3.2 6項目評価パネル（ScorePanel / ScoreBar）

算出できた項目のみ点数を表示し、データが無い項目は**「未算出」＋理由**を表示する。
未算出を0点として扱わないのが要点。0点にすると「評価が低い」のか「測っていない」のかが
区別できなくなり、鮮度保証の方針に反する。

| 項目 | 配点 | 状態 | 算出根拠 / 未算出の理由 |
|---|---|---|---|
| ① カタリスト | /20 | ❌ 未算出 | 決算発表予定日を取得する手段がない |
| ② モメンタム | /20 | ✅ | EDINET年次推移の前年比（純利益10 + 経常利益6 + 売上4） |
| ③ 需給・テクニカル | /15 | ❌ 未算出 | 信用倍率・出来高を取得していない |
| ④ バリュエーション | /15 | ✅ | PER 8点 + PBR 7点。PERがnullの銘柄はPER分を加点しない |
| ⑤ 下値リスク | /15 | ✅ | 自己資本比率（70%以上=15 … 30%未満=2） |
| ⑥ 配当 | /15 | ⚠️ 部分 | 配当利回りのみ（最大12点）。連続増配ぶん3点は未取得 |

- ヘッダーに「獲得点 / 算出できた満点」と「未算出N点ぶん」を併記する
- バー色：達成率 ≥75% emerald / ≥50% blue / 未満 amber
- 未算出の項目は斜線ストライプのグレーバーで表示する
- 算出ロジックは `scripts/edinet_fetcher.py > calc_score_breakdown()`
- 値は `screening_result.json` 経由で `data.ts > screeningStocks[].scoreBreakdown` に入る

**直近決算サマリー**（未実装）

売上高・営業利益・純利益の前年同期比、通期進捗率、修正、特別損益、次回決算予定日を
表示する設計だったが、算出に必要なデータを取得していないため実装していない。
実装していない項目を画面に出すと、あるはずのものが無いのか測っていないのかが
区別できなくなるため、表示自体を置いていない。

### 3.3 罠検出パネル（TrapPanel）

罠検出10ルールの結果を **該当 / 判定不能 / 確認済み** の3状態で表示する。
ルールの定義は `data_sources.md` §5.6。

| 表示 | 条件 | スタイル |
|---|---|---|
| ヘッダー | 常時 | 「該当 N · 判定不能 N · 確認済み N」（確認済み = 10 − 該当 − 判定不能） |
| ⚠ 該当した項目 | `trapReasons.length > 0` | `bg-amber-50 / border-amber-200`。理由を箇条書き |
| ? 判定不能 | `trapUndetermined.length > 0` | `bg-gray-50 / border-gray-200`。「ルール名: 測れない理由」を箇条書き＋注記「これらは『問題なし』ではなく『測っていない』項目です」 |
| ✓ 全ルール該当なし | 両方が空 | `bg-emerald-50 / border-emerald-200` |

判定不能をグレーで控えめに出すのは、警告ではないため。
ただし件数はヘッダーに必ず出し、存在自体は隠さない。

### 3.4 鮮度ラベル（FreshnessLabel）

「取得元バッジ / Qn決算 M/D / N日前 / [タグ]」を並べる。
日数もタグも `src/freshness.ts` で描画時に計算する（閾値のコピーを画面側に持たない・BUG-013）。
基準日が無い銘柄は「基準日なし」＋ `critical`。

### 3.5 一次資料リンク（SourceLinks）

「データ取得情報」ボックスの末尾に「一次資料で確認する」として配置する。

| リンク | 参照 | 無い場合 |
|---|---|---|
| 有報 ↗ | `edinetDetails[].edinetUrl` | リンクを描画しない |
| 決算短信 ↗ | `edinetDetails[].earningsPdfUrl` | 同上 |

両方とも無い場合は「一次資料のURLを取得できていません」と表示する（押せないリンクは作らない）。
リンク右に `earningsTitle` を補足表示する。`target="_blank" rel="noopener noreferrer"`。

## 5. データソース

- `data.ts > screeningStocks` の全社（2026-09-01 実行分では15社）
- 6項目評価は同配列の `scoreBreakdown`
- 罠検出は同配列の `trapReasons` / `trapUndetermined`
- 一次資料リンクは `data.ts > edinetDetails` の `edinetUrl` / `earningsPdfUrl` / `earningsTitle`
- `deepStocks` / `DeepStock` 型は 2026-09-10 に削除（BUG-008）
